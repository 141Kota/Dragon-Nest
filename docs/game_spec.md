# 仕様書（仮称: DragonNest）

## 概要
卵を探して拾い、孵してドラゴンを集める、iPhone向けの短時間プレイゲーム。
家族が隙間時間に遊べることと、作る側が拡張し続けて楽しいことが目的。
既存の実装を土台に、この仕様に合わせて作り直す。

## 技術方針
- iPhoneのSafariで動くHTML/JavaScript（フレームワークなし、Canvas描画）
- 縦画面・タップとドラッグ中心の操作
- 素材は画像ファイルを使わず、すべてコードで描く（ベクター調）
- セーブはlocalStorage（読み込みに失敗しても落ちない作り）
- 公開はGitHub Pages。リポジトリ直下の index.html から起動できる構成
- データ（場所・卵・ゴブリン・バトル・ドラゴンのパーツ・施設）は1か所の定義にまとめ、追加しやすくする

## 全体の雰囲気
- 色は落ち着いた深みのある彩度にしつつ、画面全体は明るくする。暗くしすぎない
- 背景・地面・UIの明るさに下限を決める（背景は中間より明るい色を基本にし、暗い色は影と夜の場所だけに使う）。文字は背景に対して十分なコントラストをとる
- 子供向けの丸くて蛍光色の配色にはしない
- 文は、ふつうの口調で短く書く。難しい単語や硬い言い回しは使わない
- 文言はひらがなを多くしすぎず、漢字とのバランスを自然にする

## UIのルール
- 文字と枠・ボタンの間は、最低でも文字の高さの半分の余白をとる
- 文字が枠に収まらないときは、自動で文字を小さくするか折り返す。重なりや枠外へのはみ出しは出さない
- ボタンは指で押せる大きさ（高さ44px以上）にして、隣のボタンと十分に離す
- スクロールできる画面（図鑑・場所選択など）は、ボタンの上からでもドラッグでスクロールできる。ボタンはタップとドラッグを区別し、指が一定距離（8px程度）動いたらスクロールとして扱ってボタンの反応を取り消す
- スクロール領域とボタンに、縦方向のパン操作を通す設定（touch-action: pan-y 相当）を入れる
- 実装後、全画面で文字の重なりと切れがないか自分で確認する

## 遊びの流れ
1. 場所を選んで探索に出る
2. フィールドを自分で歩き、卵や宝を探す
3. ゴブリンに出くわすとバトル（ミニゲーム）になる
4. 拠点に戻り、卵を置いて孵化を待つ
5. ドラゴンが孵り、図鑑と拠点が育つ

## 探索
- 左下の仮想スティックで、前後左右に自由に歩く
- 画面は斜め上からの見下ろし。カメラはキャラを追い、奥に行くほどキャラが少し小さくなる
- 背景は手前・中間・奥の層で動く速さを変え、岩や木はキャラの前後に回り込める
- 小さめのフィールドで、端から端まで1分ほど。崖・川・茂みで道を作り、寄り道する理由を置く
- フィールドに卵の巣・宝箱・泉・ゴブリンの足跡などを散らす。足跡に先に気づくと、バトルを有利に始められる
- ゴブリンはフィールド上を歩いていて、プレイヤーに気づくと襲いかかってくる（下の「ゴブリンの行動」を参照）
- 場所ごとに背景と天気を変える（最初は森・海・火山の3か所）
- 探索に出ると、拠点で孵化中の卵の残り時間が少し縮む

## バトル
参考: マリオパーティのミニゲーム。短くて、ルールが1行で分かり、毎回違う遊びになる。

### 共通の枠
- 開始前にルール説明カードを出す：バトル名・1行のルール・操作アイコン・「始める」ボタン
- 説明カードもバトル中も、探索していたフィールドをそのまま背景に映す。暗くする幕は掛けない。ステージ内のバトルだと分かることが目的
- 説明カードは画面の上か下に小さく置き、フィールドとキャラを隠さない
- バトルはフィールドの現在地の周りで始まる（ゴブリンが出た位置・プレイヤーの位置のまま、カメラだけ少し寄る）
- 1回20〜40秒で終わる
- 結果は「大成功・成功・失敗」の3段階。報酬（卵の数・アイテム）が変わる
- 失敗しても探索には戻れる（卵を1つ奪われる）
- 終了時に短い結果演出を出す
- 全バトルが同じ入口と出口を持つ（入る：連れているドラゴンとゴブリンの種類。出る：結果の段階と報酬）
- 各バトルは独立した1ファイルにして、追加は「ファイルを足し、データに1行足す」だけにする
- ゴブリンの種類ごとに、使うバトルとバトル内の癖を指定できる

### ドラゴンの影響
- ドラゴンは「力・速さ・器用さ・知恵」の4つの得意を持つ
- どのバトルでも得意が効き、バトルによって連れていくドラゴンを変えたくなるようにする
- 連れていくのは最大3体

### 最初に作る5種類
1. **追跡**: 卵を持って逃げるゴブリンを、スティックで追う。ドラゴンの技ボタンで足止めして逃げ道をふさぐ（アクション）
2. **罠解除**: 卵に仕掛けられた罠を、順番を考えて解く。ドラゴンの得意で、ヒントや解除の手助けが変わる（パズル）
3. **包囲**: 小さな盤面にドラゴンを置いて、ゴブリンの進路をふさぐ（作戦）
4. **防衛**: 卵を守りながら、押し寄せる数体のゴブリンをタップで迎え撃つ（忙しさと手際）
5. **太鼓**: ゴブリンの太鼓に合わせてタップし、ドラゴンが踊って気をそらす（リズム）

## 孵化
- 卵を拠点に置くとリアルタイムで孵る（短め・最長30分程度）。レア卵ほど長い
- 置ける卵は最初は2個
- アプリを開いたときに時間が過ぎていれば孵化済みにする（通知は使わない）
- 探索とアイテム（ぬくもり石）で残り時間を縮められる
- アイテムは探索とバトルの報酬のみ。課金や広告は入れない

## ドラゴン
- 色違いに見えない、シルエットで別と分かる見た目にする
- **つぎはぎに見せない**：系統ごとに、首・胴・しっぽをつなぐ1本の骨組み（関節の連なり）を持たせ、体は骨組みに沿った1つの連続した輪郭で描く。パーツを別々に重ねない
- 角・背びれ・装飾品・模様は、骨組みの決まった点に取り付け、体と同じ線の太さと陰影のルールで描く。つなぎ目はなじませる
- 動きは骨組みの動きから作る：息で胴が上下し、首としっぽは根元から先へ少しずつ遅れて追従し、翼は付け根から動く。パーツが個別にバラバラ動かない
- 全体に同じ陰影（光の向きは1つ）を付ける
- **360°対応**：ドラゴン・ゴブリン・プレイヤーは、骨組みを3D座標（前後・左右・高さ）で持つ。向きの角度に合わせて骨組みを回転させ、2Dに投影して描く。胴・首・しっぽ・手足は、太さが変わる円筒や楕円でつなぎ、奥にあるものから順に描く（奥行き順）。描画は2Dのままでよい
- 向きは、移動方向になめらかに回る（急に切り替えない）。正面・背面・斜めのときも、翼・角・耳・しっぽの見え方が自然に変わる
- 立ち止まっているときは、直前の向きを保つ。バトル中は、相手の方を向く
- 同時に多数が映る場面（図鑑・拠点）では、描画を軽くする（画面外のものは描かない・小さいものは簡易描画にする）

### かっこよく見せる描き方
- 輪郭線は細くする（太い黒線は使わない）。線は塗りより少し暗い同系色にして、光が当たる側は線を薄くするか消す
- 塗りは1色にせず、光の向きに合わせたグラデーションにする（上が明るく下が暗い・背中側に縁の光・関節や脇に落ちる影）
- 体の下に接地の影を落とす。体の表面にうろこ・筋・つやの小さな反射を入れる
- シルエットを鋭くする：とがった吻、眉の骨のはり出し、後ろへ流れる角、背に並ぶ背びれ、先へ向かって細くなる首としっぽ
- 翼は、骨のすじと半透明の膜でできた形にする（光が透ける）。羽ばたきは付け根から先へ遅れて動く
- 目は小さく鋭くして、わずかに光らせる。口や鼻から、ときどき息や火の粒を出す
- 左右を完全な対称にしない（傷・欠けた角・片側だけの飾り）。個体ごとに違いを出す
- 系統ごとに歩き方と待機の動きを変える（蛇型はくねり、四足型は歩幅のある歩き、翼竜型は翼を広げる等）
- **系統（骨組み）を5〜6種類**用意する：蛇型・四足型・翼竜型・二足型・多頭型・小型の浮遊型など。系統ごとに別の骨組みを持つ
- 各系統に、角・翼・背びれ・しっぽ・鱗の模様・装飾品（鎧・宝石・傷・飾り）を組み合わせる。パーツ側は同じ系統の接続点に合わせる
- 色は最後の要素にする。色違いだけで種類を稼がない
- 場所ごとに出る系統とパーツの組み合わせを決める
- 色違いのレア個体を混ぜる
- 同じドラゴンが再び孵るとレベルが上がる（技が増える・強くなる・見た目が少し変わる）
- 判断基準：図鑑を並べたとき、同じに見えるドラゴンが続かないこと

## ゴブリンとプレイヤー
- ゴブリンは、ちゃんとかっこいい見た目にする：少し猫背の細身の体、大きくとがった耳、つり目、牙、ぼろぼろの装束や革の防具と武器。ドラゴンと同じ骨組み方式で描き、動きも同じように滑らかにする
- ゴブリンの種類（盾持ち・罠師・足が速いもの・斧持ち等）は、体格・装備・色でシルエットから区別できるようにする
- プレイヤーも同じ骨組み方式で描き、ゴブリンとドラゴンと同じ線の太さ・陰影・頭身バランスにそろえる。ドラゴンを連れる冒険者らしい装い（外套・革の装備・道具袋）にする
- プレイヤーとゴブリンは、歩き・走り・立ち・勝利・失敗の動きを持つ

### ゴブリンの行動
- 状態は、見回り → 気づく → 追跡 → 見失う → 戻る の流れにする
- **見回り**：決まった範囲をゆっくり歩く。種類によって、立ち止まって周りを見る・巣のまわりを回る等の癖をつける
- **気づく**：視界（前方の扇形・一定の距離）にプレイヤーが入ると気づく。後ろや横は見えにくい。走ると気づかれる距離が伸び、茂みに入ると縮む。気づいた瞬間に「！」を出し、プレイヤーの方を向いて短く止まる
- **追跡**：向きをプレイヤーに合わせ、走って追いかける。速さは種類ごとに違う（足の速いものはプレイヤーより速い）
- **接触**：触れたらバトルになる。気づかれる前に先に近づく・後ろから触れると、バトルを有利に始められる
- **見失う**：プレイヤーが視界から外れ、一定時間たつと「？」を出して探す。それでも見つからなければ、見回りに戻る
- 逃げることもできる：追跡中のゴブリンは、一定の距離を離れるか、崖・川・茂みの向こうへ行けば、あきらめる
- 複数のゴブリンが近くにいるときは、1体が気づくと周りも少し遅れて気づく

## 図鑑
- 未発見はシルエット表示
- 場所ごとにページを分け、埋まり具合を表示する
- 見た目を重視する（大きく見やすく、ゆっくり動く）
- 系統や得意の表示も出す

## 拠点
- 斜め視点の2Dで、奥行きを出す（影・グラデーション・手前と奥の重なり）
- 施設を足すと孵化やバトルが強化される（拡張向け）

## 見た目の方針
- 2Dのベクター調。奥行きは影・グラデーション・重なりで出す
- ドラゴンの動き（息・羽ばたき・しっぽ）を小さく付ける

## 最初の実装範囲
- 場所3か所、ゴブリン3種類以上、バトル5種類、ドラゴンの系統5種類以上
- 探索・バトル・孵化・図鑑・拠点（施設は2〜3種類）まで一通り遊べる状態

## 決めていないこと
- ゲーム名
- 施設の具体的な種類
- バトルやドラゴンの数値（遊びながら調整する）
